# Инструкции по рефакторингу Libr4 для ИИ-агентов (Уровень: Expert)

Этот документ предназначен для скармливания ИИ-агенту вместе с задачей. Он ограничивает область поиска и диктует правила реализации.

---

## 🛠 Гайд №1: Миграция с InMemory на EF Core (Persistence)

**Проблема:** Данные хранятся в Dictionary.

**Инструкция для агента:**

### Анализ
Найди класс `InMemory[Entity]Repository`. Выпиши список методов.

### Создание сущности
Создай класс в `Infrastructure/Persistence/Configurations/` для настройки Fluent API.

### Реализация
1. Создай новый класс `Ef[Entity]Repository`.
2. Используй `DbSet<Entity>` для всех операций.
3. **Важно:** Не используй Lazy Loading. Всегда добавляй `.AsNoTracking()` для методов чтения (Get).

### Регистрация
Найди `DependencyInjection.cs` и замени `AddSingleton<I...Repository, InMemory...>` на `AddScoped<I...Repository, Ef...Repository>`.

## 🛡 Гайд №2: Удаление "Тихих сбоев" (Empty Catches)

**Проблема:** Блоки `catch { }` скрывают ошибки.

**Инструкция для агента:**

### Поиск
Найди все `catch { }` без кода внутри.

### Логирование
Добавь инъекцию `ILogger<ClassName>` в конструктор (если её нет).

### Исправление
- Если метод возвращает `Task`, запиши `_logger.LogError(ex, "Message")` и выброси исключение заново (`throw;`), если это критический узел.
- Если метод в F#, замени возвращаемое значение на `Result.Error`.

### Приоритет
Начни с `WatermarkingService.cs`.

## 🔒 Гайд №3: Очистка Секретов (Hardcoded Secrets)

**Проблема:** JWT ключи и пароли в коде.

**Инструкция для агента:**

### Поиск
Найди строки, содержащие `"Key"`, `"Secret"`, `"Password"`, где значение задано строковой константой.

### Абстракция
1. Добавь поле в `appsettings.json` (например, `"Security:JwtKey": ""`).
2. В коде используй `_configuration["Security:JwtKey"]`.

### Fallback
Создай метод-проверку при запуске: если значение из конфига `null` или `"default"`, приложение должно выдать Fatal Error с инструкцией по установке Env Var.

## 🧪 Гайд №4: Интеграция Rust Sandbox (Harness)

**Проблема:** `SandboxExecutorService` равен `null`.

**Инструкция для агента:**

### Контракт
Проверь интерфейс `ISandboxExecutor`.

### Инъекция
В `HarnessEnvironment.cs` удали инициализацию `= null`. Добавь интерфейс в конструктор.

### Реализация
1. Создай `RustSandboxClient.cs`.
2. Реализуй отправку кода через `HttpClient` или gRPC на порт 9090 (где живет твой Rust-контроллер).

### DOCKER
Убедись, что в `docker-compose.yml` сервис `sandbox-controller` имеет алиас, доступный из сети .NET сервиса.

## 🧠 Советы для работы с бесплатными ИИ (Prompt Engineering)

### Правило "Одного Файла"
Никогда не проси бесплатного агента пофиксить всё сразу. Давай ему один `.cs` файл и один гайд из этого списка.

### Запрет на "Rest of code"
Всегда добавляй фразу: `"Write the full code of the file. Do not use placeholders or comments like '// rest of code'."`

### Проверка через компиляцию
После каждого изменения проси агента: `"Check if you changed any method signatures that might break other classes."`

### Chain of Thought
Сначала пиши: `"Проанализируй файл X и скажи, какие правила из Гайда №... нарушены. Не пиши код, просто перечисли."` И только вторым сообщением: `"Теперь исправь их."`
